## Details

### mini_swe_runner.py

**Purpose:** Lightweight agent runner for software engineering tasks, producing Hermes-format trajectories.

**Key Components:**
- **`_effective_temperature_for_model()`** — Delegates to `agent.auxiliary_client._fixed_temperature_for_model` for models with strict sampling contracts (e.g., Kimi requires temperature omission).
- **`TERMINAL_TOOL_DEFINITION`** — Inline OpenAI-format tool schema for a `terminal` function accepting `command` and optional `timeout`.
- **`create_environment()`** — Factory returning `LocalEnvironment`, `DockerEnvironment`, or `ModalEnvironment` from `tools.environments.*`.
- **`MiniSWERunner` class:**
  - `__init__` — Initializes LLM client via explicit `api_key`/`base_url` or falls back to `agent.auxiliary_client.resolve_provider_client("openrouter")` then `"auto"`.
  - `run_task()` — Iterative loop: builds API messages, calls `client.chat.completions.create()`, executes tool calls via `_execute_command()`, detects `MINI_SWE_AGENT_FINAL_OUTPUT` completion signal.
  - `_convert_to_hermes_format()` — Translates internal message list to `from`/`value` trajectory format with `<tool_call>/</tool_call>` tool-call XML and `/` reasoning tags.
  - `run_batch()` — Sequential batch execution writing JSONL output.
- **`main()`** — CLI entry point via `fire.Fire()`, accepting `--task`, `--prompts_file`, `--env`, `--model`, etc.

**Notable Design Choices:**
- Environment created per-task and cleaned up in `finally` block.
- System prompt is ephemeral (not saved to trajectory).
- Tool responses include `output`, `exit_code`, and `error` fields.
- Temperature handling respects `OMIT_TEMPERATURE` sentinel from auxiliary_client.
