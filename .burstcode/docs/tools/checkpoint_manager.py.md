## Summary

Transparent filesystem snapshot manager leveraging a shared git object store to deduplicate checkpoints across projects. Provides automatic pre-operation snapshots, rollback capabilities, and automated pruning based on retention policies and size caps.

## Details

- **Shared Git Store**: Uses a single bare-ish git repo under `~/.hermes/checkpoints/store/` with per-project refs and indexes to deduplicate blobs across worktrees and turns.
- **Git Environment Isolation**: Nullifies global/system git configs and drops inherited `GIT_*` vars to prevent interactive prompts (e.g., GPG signing) or credential helper interference during background snapshots.
- **Turn Lifecycle & Dedup**: `CheckpointManager` tracks checkpointed directories per turn via `new_turn()` and `ensure_checkpoint()`, ensuring at most one snapshot per directory per agent iteration.
- **Pruning & Size Caps**: Automatically drops commits exceeding `max_snapshots` per project and enforces a global `max_total_size_mb` ceiling by round-robin dropping oldest checkpoints across all projects.
- **Legacy Migration**: One-time archival of pre-v2 per-project shadow repos into `legacy-<timestamp>/` directories, subject to the same retention sweep.
- **Validation & Safety**: Strict regex validation for commit hashes and path traversal guards prevent git argument injection and directory escapes during restore operations.
