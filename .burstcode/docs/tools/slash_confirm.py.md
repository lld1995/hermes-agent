## Slash Confirm Module

- **Purpose**: Provides a reusable confirmation flow for non-destructive but expensive slash commands (e.g., `/reload-mcp`).
- **Two delivery paths**:
  - **Button UI**: Adapters overriding `send_slash_confirm` render Approve Once / Always Approve / Cancel buttons; callbacks invoke `resolve()`.
  - **Text fallback**: Adapters without button support get a plain-text prompt; users reply with `/approve`, `/always`, or `/cancel`, intercepted by the gateway's message handler.
- **State storage**: Module-level `_pending` dict keyed by `session_key`, protected by `threading.RLock`. New confirmations for the same session overwrite stale ones.
- **Timeout handling**: `DEFAULT_TIMEOUT_SECONDS = 300`; `clear_if_stale()` drops expired entries; `resolve()` also checks staleness before executing the handler.
- **Resolution**: `resolve()` pops the entry before running the handler to prevent duplicate callbacks (e.g., button double-click); returns the handler's output string or `None` on failure/staleness.
- **Thread safety**: `resolve_sync_compat()` bridges synchronous platform callbacks (e.g., Discord button handlers on separate threads) to the asyncio event loop via `run_coroutine_threadsafe`.
- **Design note**: Mirrors the module-level state pattern used by `tools.approval`, enabling platform adapters to resolve callbacks without backreferences to `GatewayRunner`.
