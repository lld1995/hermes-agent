## Details

### `tools/computer_use/tool.py`

**Purpose:** Entry point for the `computer_use` tool — universal macOS desktop control via `cua-driver`.

**Key features:**
- **Approval gating:** Destructive actions (`click`, `type`, `key`, `drag`, etc.) route through `_approval_callback` with `approve_once`/`approve_session`/`always_approve`/`deny` verdicts. Safe actions (`capture`, `wait`, `list_apps`) bypass approval.
- **Hard blocks:** Key combos like `cmd+shift+q` (logout) and `cmd+ctrl+q` (lock screen) are permanently blocked. The `type` action rejects shell injection patterns (`curl | bash`, `sudo rm -rf`, fork bombs).
- **Backend selection:** Lazily instantiated via `_get_backend()`, swappable via `HERMES_COMPUTER_USE_BACKEND` env var (`cua` or `noop` for tests). Thread-safe with `_backend_lock`.
- **Multimodal responses:** Capture actions return `_multimodal` dicts with base64 images + element summaries. `run_agent.py` and `agent/anthropic_adapter.py` handle provider-specific splicing.
- **Action dispatch:** Supports `capture`, `click`, `double_click`, `right_click`, `middle_click`, `drag`, `scroll`, `type`, `key`, `set_value`, `focus_app`, `wait`, `list_apps`. Optional `capture_after=True` appends a post-action screenshot.
- **Availability check:** `check_computer_use_requirements()` gates on macOS + `cua-driver` binary presence.

**State:** Module-level `_session_auto_approve` and `_always_allow` track per-session approval state. No `ContextVar` isolation — relies on gateway worker boundaries.
