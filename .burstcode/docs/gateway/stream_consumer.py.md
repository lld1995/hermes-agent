## Summary

Async streaming consumer that bridges synchronous agent token callbacks to progressive platform message delivery. Handles edit-based streaming, native draft frames, flood-control backoff, think-block filtering, and overflow chunking.

## Details

- **Thread-safe ingestion**: `on_delta()` pushes text into a `queue.Queue`; `run()` drains it asynchronously.
- **Transport modes**: `"edit"` (progressive `editMessageText`), `"draft"` (native `send_draft` frames), or `"auto"` (adapter-probed). Drafts fall back to edit on first failure.
- **Think-block filtering**: State machine strips `<reasoning>`, ``, etc., respecting block boundaries to avoid false positives in prose.
- **Flood control**: Adaptive backoff doubles `edit_interval` on consecutive flood errors; after 3 strikes, permanently disables edits and enters fallback mode.
- **Fallback path**: When edits fail, `_send_fallback_final()` delivers only the unseen tail as new messages, best-effort deleting the frozen partial.
- **Overflow handling**: Splits oversized text using `adapter.truncate_message()` or `_split_text_chunks()`, respecting platform `MAX_MESSAGE_LENGTH` and custom `message_len_fn` (e.g., UTF-16 for Telegram).
- **Segment breaks**: `on_segment_break()` finalizes the current message so tool-progress bubbles appear chronologically below content.
- **Fresh-final logic**: `fresh_final_after_seconds` replaces long-lived previews with a new message so the visible timestamp reflects completion time.
- **Media directive stripping**: `_clean_for_display()` removes `MEDIA:<path>` and `[[audio_as_voice]]` tags before display.
