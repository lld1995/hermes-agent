## Summary

Network resilience helpers for Telegram providing a fallback HTTP transport. Discovers reachable API IPs via DNS-over-HTTPS, preserves TLS SNI, and caches sticky fallback addresses when the primary domain is unreachable.

## Details

- Implements `TelegramFallbackTransport` extending `httpx.AsyncBaseTransport`
- Retries TCP connections against fallback IPs while preserving logical host and TLS SNI
- Discovers IPs via Google/Cloudflare DNS-over-HTTPS, falling back to hardcoded seed IPs
- Validates and normalizes fallback IPs (IPv4 only, rejects private/loopback)
- Caches a "sticky" fallback IP after successful connection to avoid repeated primary-path failures
- Integrates with shared proxy resolution (`resolve_proxy_url`) for both primary and fallback paths
- Handles connection timeouts and errors gracefully, escalating only when all paths fail
- Designed for networks where `api.telegram.org` DNS resolves to unreachable endpoints
