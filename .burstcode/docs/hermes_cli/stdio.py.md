## Summary

Windows-safe stdio configuration module that forces UTF-8 encoding on Windows consoles, sets default editor, and augments PATH with Hermes-managed tool directories to fix first-launch resolution gaps.

## Details

- Solves `UnicodeEncodeError` on Windows by flipping the console code page to UTF-8 (65001) via `ctypes.windll.kernel32.SetConsoleCP/SetConsoleOutputCP` and reconfiguring Python's `sys.stdout/stderr/stdin` wrappers with `encoding='utf-8', errors='replace'`.
- Idempotent: guarded by `_CONFIGURED` global; safe to call from multiple entry points (`cli.py`, `main.py`, `gateway/run.py`).
- Sets `PYTHONIOENCODING=utf-8` and `PYTHONUTF8=1` via `os.environ.setdefault()` so child Python processes inherit UTF-8 mode (PEP 540).
- Sets a default `$EDITOR` on Windows (`notepad`) if neither `EDITOR` nor `VISUAL` is set, fixing `prompt_toolkit`'s POSIX-only fallback paths.
- `_augment_path_with_known_tools()` prepends Hermes-managed directories (`%LOCALAPPDATA%\hermes\git\{cmd,bin,usr\bin}`, `venv\Scripts`, `WinGet\Links`) to `os.environ['PATH']` to close the gap between installer's User-scope PATH writes and already-running shells.
- No-op on non-Windows platforms; opt-out via `HERMES_DISABLE_WINDOWS_UTF8=1`.
- Uses case-insensitive deduplication (`existing_lower` set) to avoid duplicate PATH entries.
