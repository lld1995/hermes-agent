## Details

Tests the `lsp_diagnostics` field on `WriteResult` and `PatchResult`:

- **Dataclass shape**: Field is optional (defaults to `None`), omitted from `to_dict()` when `None` or empty string, included when set
- **Channel separation**: `WriteResult` can carry both `lint` (syntax errors) and `lsp_diagnostics` (semantic errors) independently
- **write_file integration**: When `_maybe_lsp_diagnostics` returns a non-empty block, it populates `lsp_diagnostics` — NOT `lint.output`
- **Empty LSP response**: Returns `None` for `lsp_diagnostics` when the layer returns empty string
- **Syntax error short-circuit**: When syntax check fails, `_maybe_lsp_diagnostics` is never called (unparseable files won't yield meaningful semantic diagnostics)
- **patch_replace propagation**: Internal `write_file` call's `lsp_diagnostics` is carried forward into the outer `PatchResult`

This separation lets the agent distinguish syntax errors from semantic/type errors as independent signals.
