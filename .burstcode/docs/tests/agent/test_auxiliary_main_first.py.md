## Summary

Regression tests for the "auto" → main-model-first policy, ensuring auxiliary tasks use the user's main chat model rather than cheap provider-side defaults, with explicit config overrides still winning.

## Details

Validates that `_resolve_auto()` in `agent.auxiliary_client` prefers the main provider + main model for all users, regardless of whether they use aggregators (OpenRouter/Nous) or direct providers.

**Text aux tasks (`_resolve_auto`):**
- OpenRouter/Nous/DeepSeek main users get their picked model for aux tasks
- When main provider has no working client, falls through to the aux chain (OpenRouter/Nous cheap backends)
- No main config → skips directly to the fallback chain
- `main_runtime` kwarg overrides config-read provider/model

**Vision tasks (`resolve_vision_provider_client`):**
- OpenRouter main with vision-capable model → uses main model with `is_vision=True`
- Nous paid main → uses dedicated Nous vision backend; free-tier → uses MiMo omni
- Exotic providers (xiaomi) preserve vision-specific model overrides
- Copilot vision requests include `Copilot-Vision-Request: true` header; text requests do not
- Explicit `auxiliary.vision.provider` config override bypasses main-first policy
