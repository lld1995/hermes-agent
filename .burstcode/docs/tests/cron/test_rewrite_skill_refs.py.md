## Summary

Tests the curator integration `rewrite_skill_refs` that updates cron job skill references after skill consolidation or pruning, ensuring jobs continue to load the correct skills at runtime.

## Details

- **No-op cases**: Empty map + no jobs, jobs exist but map empty (early return, no scan), jobs exist but no matches (scanned but untouched).
- **Consolidation**: Replaces legacy skill names with umbrella targets; preserves ordering; dedupes when umbrella already present; rewrites legacy `skill` field alongside `skills` list.
- **Pruning**: Drops pruned skills outright; empty skill list leaves `skill=None`.
- **Mixed**: Consolidation takes priority over pruning when a skill appears in both maps.
- **Multiple jobs**: Only affected jobs are reported; untouched jobs remain unchanged.
- **Persistence**: Rewrites survive disk reload; noop passes skip disk writes entirely (mtime unchanged).
- **Report**: Returns `rewrites` list with `before`/`after`/`mapped`/`dropped` per job, plus `jobs_updated` and `jobs_scanned` counts.
