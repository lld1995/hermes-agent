## Summary

Async LSP client over stdin/stdout. Manages a single language server subprocess, JSON-RPC exchange, file synchronization, and diagnostic push/pull with deduplication and retry logic.

## Details

### Purpose
One `LSPClient` per `(language_server, workspace_root)` pair. Owns the child process, drives JSON-RPC, and exposes file sync and diagnostic APIs.

### Lifecycle
- **`start()`**: Spawns process, runs initialize handshake, transitions to `running`.
- **`shutdown()`**: Sends `shutdown` + `exit` notifications, then SIGTERM/SIGKILL fallback.
- **`_cleanup_process()`**: Cancels reader/stderr tasks, terminates process.

### Key APIs
- **`open_file(path)`**: Sends `didOpen` (first time) or `didChange` (subsequent). Fires `didChangeWatchedFiles` notification.
- **`wait_for_diagnostics(path, version)`**: Blocks until fresh push or pull diagnostics arrive (5s/10s budget).
- **`diagnostics_for(path)`**: Returns merged, deduped diagnostics from push and pull stores.

### Design Notes
- Whole-document sync: always sends full replacement regardless of server's incremental capability.
- `ContentModified` (-32801) errors retried with exponential backoff (0.5s, 1.0s, 2.0s).
- Push diagnostics stored per-URI; pull diagnostics stored separately. Merged view dedupes by content key.
