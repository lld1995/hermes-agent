## Summary

Structured logging for the LSP layer with once-per-X deduplication. Prevents log spam by emitting state transitions at INFO/WARNING exactly once per session, while keeping diagnostic events at INFO every time.

## Details

### Purpose
Provides steady-state silence for LSP logging. Users can `rg` the log for diagnostic events without drowning in noise.

### Level Model
- **DEBUG**: Steady-state events (clean, feature off, extension not mapped). Silent at default INFO threshold.
- **INFO**: State transitions once per session (active client, no project root first time). Every diagnostic event.
- **WARNING**: Action-required failures (server unavailable, no server configured, timeouts, unexpected errors).

### Dedup Mechanism
- Module-level sets (`_announced_active`, `_announced_unavailable`, etc.) with thread-safe `_announce_once()`.
- Keys are tuples like `(server_id, workspace_root)` or `(server_id, binary_path)`.
- Bounded by distinct pairs touched in one process — no LRU eviction to avoid re-firing suppressed lines.
