## Summary

Entry point for LSP integration. Provides a process-wide singleton `LSPService` via `get_service()`, with lazy initialization, atexit cleanup, and explicit `shutdown_service()` for manual teardown.

## Details

### Purpose
Manages the lifecycle of the LSP service singleton that runs language servers as subprocesses for post-write semantic diagnostics.

### Key Functions
- **`get_service()`**: Returns the singleton `LSPService` or `None` if disabled. Uses double-checked locking. Registers an `atexit` handler on first creation.
- **`shutdown_service()`**: Tears down the service and spawned servers. Safe to call multiple times.
- **`_atexit_shutdown()`**: atexit-registered wrapper that calls `shutdown_service()`.

### Design Notes
- LSP is gated on git workspace detection — disabled outside git repos to avoid spawning unnecessary daemons.
- `atexit` handlers run on normal exit and `SystemExit`, but not on `os._exit()` or uncaught signals. Language servers are stateless subprocesses, so kernel reaping on SIGKILL is acceptable.
- The bulk of wiring is internal; callers typically interact via `tools.file_operations.FileOperations._check_lint_delta`.
