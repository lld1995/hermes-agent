## Summary

Abstract base class for web search/extract/crawl backends, defining a unified plugin-facing surface that preserves the legacy response-shape contract from tools.web_providers.base.

## Details

Web search provider ABC with three capabilities: search, extract, crawl.

- **WebSearchProvider (ABC)**: Subclasses implement `name` and `is_available()`. Must implement at least one of `search()`, `extract()`, `crawl()`.
- **Capability flags**: `supports_search()` (default True), `supports_extract()` (default False), `supports_crawl()` (default False). Let multi-capability providers (Firecrawl, Tavily, Exa) advertise multiple capabilities.
- **search(query, limit)**: Returns `{"success": True, "data": {"web": [...]}}` with title/url/description/position per result.
- **extract(urls, **kwargs)**: Returns list of `{url, title, content, raw_content, metadata, error}` dicts. May be async — dispatcher detects coroutines via `inspect.iscoroutinefunction`.
- **crawl(url, **kwargs)**: Returns `{"results": [...]}` for seed-URL crawling. Only Tavily and Firecrawl implement this natively.
- **get_setup_schema()**: Returns metadata for `hermes tools` picker (name, badge, tag, env_vars with API key prompts).
- Replaces legacy `tools.web_providers.base` ABCs deleted in PR #25182.
