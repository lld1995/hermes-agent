## Summary

Routing helpers that decide whether user-attached images are sent as native multimodal content parts or pre-analyzed via text-based vision. Includes MIME sniffing, base64 data-URL encoding, and OpenAI-style content part construction.

## Details

### Purpose
Determines per-turn image input mode (`native` vs `text`) based on config (`agent.image_input_mode`) and active model capabilities.

### Key Functions
- **`decide_image_input_mode`**: Returns `"native"` or `"text"`. In `auto` mode, prefers native if the model reports `supports_vision=True`; falls back to text if an explicit auxiliary vision provider is configured.
- **`build_native_content_parts`**: Constructs an OpenAI-style `content` list with `image_url` parts and path hints appended to the text part. Returns skipped paths for unreadable files.
- **`_sniff_mime_from_bytes`**: Detects MIME type from magic bytes (PNG, JPEG, GIF, WEBP, BMP, HEIC) to avoid provider rejections from mismatched `media_type`.
- **`_file_to_data_url`**: Reads file bytes, guesses MIME, and returns a base64 data URL at native size.

### Design Notes
- Image shrinking is **reactive**, not proactive. Full-size images are attached first; `run_agent._try_shrink_image_parts_in_messages` shrinks and retries on provider rejection (e.g., Anthropic's 5 MB ceiling).
- MIME sniffing is authoritative over filename-based detection to handle platforms like Discord that mislabel content types.
