## Details

- `CodexAppServerClient` spawns `codex app-server` subprocess with configurable bin path, home dir, and env
- Threading model: caller drives requests synchronously; daemon reader threads parse stdout (dispatching replies/notifications) and capture stderr
- `request()` sends JSON-RPC request, blocks on response queue with timeout, raises `CodexAppServerError` on error
- `notify()` sends fire-and-forget notifications; `respond()`/`respond_error()` reply to server-initiated requests
- `take_notification()` and `take_server_request()` pop from bounded queues (non-blocking or timed)
- `_dispatch()` routes messages by structure: replies (id+result/error), server requests (id+method), notifications (method only)
