## Summary

Defines canonical dataclasses (ToolCall, Usage, NormalizedResponse) that all provider adapters normalize their API responses into, with backward-compatibility properties for legacy agent loop access patterns.

## Details

Shared response normalization types for the multi-provider transport layer.

- **ToolCall**: Normalized tool call with `id`, `name`, `arguments` (JSON string), and `provider_data` for protocol-specific metadata (Codex call_ids, Gemini thought_signatures). Backward-compat properties (`type`, `function`, `call_id`, `response_item_id`, `extra_content`) let the agent loop access fields via legacy dotted paths like `tc.function.name`.
- **Usage**: Simple token usage dataclass with `prompt_tokens`, `completion_tokens`, `total_tokens`, `cached_tokens`.
- **NormalizedResponse**: Canonical response shape with `content`, `tool_calls`, `finish_reason`, `reasoning`, `usage`, and `provider_data`. Backward-compat properties expose Anthropic reasoning_details, Codex reasoning/message items.
- **Factory helpers**: `build_tool_call()` auto-serializes dict arguments to JSON and collects extra kwargs into `provider_data`. `map_finish_reason()` translates provider-specific stop reasons to the normalized set (`stop`, `tool_calls`, `length`, `content_filter`).
