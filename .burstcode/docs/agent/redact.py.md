## Summary

Regex-based secret redaction engine for logs and tool output. Masks API keys, tokens, credentials, private keys, DB connection strings, JWTs, Discord mentions, and phone numbers before they reach log files or verbose output.

## Details

- **Pattern coverage**: 30+ vendor prefix patterns (sk-, ghp_, xox-, AIza, fal_, fc-, etc.), ENV assignments (`API_KEY=...`), JSON fields (`"apiKey": "..."`), Authorization headers, Telegram bot tokens, private key blocks, DB connection strings, JWTs, URL userinfo, URL query params, form-urlencoded bodies, Discord snowflake mentions, and E.164 phone numbers.
- **`redact_sensitive_text()`**: Main entry point. Applies all patterns in sequence. Respects `HERMES_REDACT_SECRETS` env var (snapshot at import time to prevent runtime disable). `force=True` bypasses the global toggle for safety boundaries. `code_file=True` skips ENV/JSON patterns to avoid false positives in source code.
- **Masking strategy**: Short tokens (<18 chars) are fully masked (`***`). Longer tokens preserve 6 prefix + 4 suffix characters for debuggability.
- **`RedactingFormatter`**: A `logging.Formatter` subclass that automatically redacts all log messages.
- **Security design**: Enabled by default (secure default per issue #17691). Opt-out requires explicit config or env var, with startup warnings logged.
