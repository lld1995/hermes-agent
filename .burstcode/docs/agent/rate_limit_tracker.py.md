## Summary

Parses `x-ratelimit-*` HTTP response headers into structured `RateLimitState` dataclasses and formats them for terminal/chat display. Supports the Nous Portal header convention (also used by OpenRouter and OpenAI-compatible APIs).

## Details

- **Data model**: `RateLimitBucket` tracks limit, remaining, reset_seconds, and capture timestamp for one window. `RateLimitState` holds four buckets (requests/tokens × min/hour) plus provider name and capture time.
- **`parse_rate_limit_headers()`**: Normalizes header keys to lowercase, checks for any `x-ratelimit-*` prefix, then extracts 12 headers into four buckets. Returns `None` if no rate limit headers are present.
- **Display formatting**: `format_rate_limit_display()` produces a multi-line report with ASCII progress bars, usage percentages, and warnings when any bucket exceeds 80%. `format_rate_limit_compact()` produces a single-line summary for status bars.
- **Time awareness**: `remaining_seconds_now` adjusts the reset countdown by elapsed time since capture. `age_seconds` reports how stale the data is.
- **Number formatting**: `_fmt_count()` abbreviates large numbers (8.0M, 33.6K). `_fmt_seconds()` converts to human durations (2m 14s, 1h 2m).
