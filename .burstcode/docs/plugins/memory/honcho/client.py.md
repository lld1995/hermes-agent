## Summary

Configuration resolution and client initialization for the Honcho memory backend. Implements a 3-tier config file fallback, host-specific setting inheritance, session name resolution strategies, and lazy SDK loading. Manages the Honcho client singleton with local/cloud deployment detection.

## Details

- **Config resolution**: `resolve_config_path` checks `$HERMES_HOME/honcho.json`, then default Hermes home, then `~/.honcho/config.json`, falling back to environment variables.
- **HonchoClientConfig dataclass**: Encapsulates workspace, API keys, observation modes, dialectic reasoning settings, session strategies, and token budgets. `from_global_config` merges host-block overrides with root-level defaults.
- **Session name resolution**: `resolve_session_name` prioritizes manual directory mappings, then session titles, gateway session keys, and strategy-based fallbacks (`per-session`, `per-repo`, `per-directory`, `global`). Enforces Honcho's 100-char ID limit via deterministic SHA-256 truncation.
- **Client singleton**: `get_honcho_client` lazily initializes the `honcho` SDK, applying config.yaml overrides for base URLs and timeouts. Detects local deployments to suppress cloud API keys.
- **Observation & dialectic parsing**: Helper functions normalize legacy mode aliases, resolve granular per-peer observation booleans, and clamp dialectic depth/levels to valid ranges.
