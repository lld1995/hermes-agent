## Summary

CLI interface for managing Honcho memory integration across Hermes profiles. Provides interactive setup, profile cloning, status inspection, session mapping, peer identity management, and OpenClaw migration workflows. Reads and writes honcho.json configuration files with host-block isolation per profile.

## Details

- **Profile cloning**: `clone_honcho_for_profile` duplicates default host settings into profile-specific blocks (`hermes.<profile>`), auto-deriving workspace and AI peer identities.
- **Interactive setup**: `cmd_setup` guides users through cloud vs. local deployment, API key entry, peer naming, observation modes, write frequency, recall modes, and token budgets.
- **Configuration I/O**: `_read_config`/`_write_config` handle JSON persistence, splitting read paths (global fallback) from write paths (profile-local `$HERMES_HOME/honcho.json`).
- **Status & inspection**: `cmd_status`, `cmd_peers`, `cmd_sessions` display active config, cross-profile host blocks, and directory-to-session mappings.
- **Migration workflow**: `cmd_migrate` detects OpenClaw native memory files (`USER.md`, `SOUL.md`, etc.) and guides users through uploading them to Honcho peers.
- **CLI registration**: `register_cli` builds the `hermes honcho` argparse subcommand tree, routing to appropriate handlers via `honcho_command`.
