## Summary

Tavily web search plugin implementing search, extract, and crawl capabilities via synchronous httpx POST calls. Handles dual auth modes (body-only for search/extract, Bearer header for crawl) and normalizes responses into a standard document shape.

## Details

- Subclasses `WebSearchProvider` with three capabilities: `supports_search`, `supports_extract`, `supports_crawl`
- `_tavily_request()` handles auth: body `api_key` for /search and /extract; Bearer header required for /crawl
- `_normalize_tavily_search_results()` maps `/search` response to `{success, data: {web: [...]}}` shape
- `_normalize_tavily_documents()` maps `/extract` and `/crawl` responses to standard document dicts with `url`, `title`, `content`, `raw_content`, `metadata`; failures become entries with `error` field
- All three methods check `tools.interrupt.is_interrupted()` before dispatching
- Config keys: `web.search_backend`, `web.extract_backend`, `web.crawl_backend`, or shared `web.backend`
- Requires `TAVILY_API_KEY` env var; optional `TAVILY_BASE_URL` override
- `get_setup_schema()` returns paid badge and env var prompt for CLI setup flow
