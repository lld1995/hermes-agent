## Summary

Core cron job storage, schedule parsing, and lifecycle management. Handles job CRUD with atomic file writes, timezone-aware scheduling (interval/cron/one-shot), grace-period catch-up for missed runs, and curator-driven skill reference rewriting.

## Details

- Stores jobs in `~/.hermes/cron/jobs.json` with atomic temp-file + rename writes via `utils.atomic_replace`
- In-process `threading.Lock` (`_jobs_file_lock`) protects load-modify-save cycles during parallel tick execution
- Schedule parsing supports durations (`30m`), intervals (`every 2h`), cron expressions (via `croniter`), and ISO timestamps
- Timezone handling: `_ensure_aware()` converts naive legacy timestamps to Hermes-configured timezone to prevent false "not due" results
- Grace-period logic (`_compute_grace_seconds`) scales with schedule period (120s–2h) to allow catch-up without burst-firing stale jobs
- `advance_next_run()` pre-emptively moves `next_run_at` before execution to prevent duplicate firing on crash restart
- `mark_job_run()` tracks success/error/delivery-error separately, increments repeat counters, and auto-deletes exhausted one-shots
- `rewrite_skill_refs()` repairs cron job skill lists after curator consolidation/pruning, mapping old skill names to umbrella targets
- `no_agent` mode runs scripts directly without LLM, delivering stdout verbatim
- `workdir` field injects directory-specific context files (AGENTS.md, etc.) and sets `TERMINAL_CWD`
