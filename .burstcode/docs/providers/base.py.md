## Summary

Declarative `ProviderProfile` dataclass defining provider metadata, auth, endpoints, model catalog, client quirks, and request-level hooks. Profiles describe behavior without owning client construction or streaming.

## Details

- `OMIT_TEMPERATURE` sentinel for providers where server manages temperature (e.g. Kimi)
- Identity fields: `name`, `api_mode`, `aliases`, `display_name`, `description`, `signup_url`
- Auth/endpoint fields: `env_vars`, `base_url`, `models_url`, `auth_type` (api_key|oauth_device_code|oauth_external|copilot|aws_sdk), `supports_health_check`
- Model catalog: `fallback_models` for picker when live fetch fails; `hostname` for URL-to-provider reverse mapping
- Client quirks: `default_headers`, `fixed_temperature`, `default_max_tokens`, `default_aux_model`
- `get_hostname()` derives hostname from `base_url` if `hostname` not explicitly set
- `prepare_messages()` hook for provider-specific message preprocessing (after codex sanitization, before developer role swap)
- `build_extra_body()` and `build_api_kwargs_extras()` hooks for provider-specific request shaping; the latter splits between extra_body and top-level kwargs for reasoning config placement
- `fetch_models()` default implementation hits `{base_url}/models` or explicit `models_url` with Bearer auth
